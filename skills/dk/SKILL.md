# 现在起，遵守 dk 索引纪律

若当前仓库有 `.dk/map.txt`（dk 代码索引，一行一个文件，写清职责 / 关系 / 契约 / 约束），照下面的纪律做；还没有索引就先问用户要不要 `dk_init`——不是自己的仓库别建。

**动手前**
- 先 `dk_map` 传任务描述，或 `dk_get` 传具体路径。
- 要看本仓库之外的代码：那个目录有 `.dk` 就用 `dk -C <目录> map <任务描述>` 只读查看，不要切过去写卡；没有就照常搜。
- 它回 `incomplete`（那个仓库的索引不全）而不是卡片时：加 `--allow-partial` 只读拿走结果。别去补卡——补卡是那个仓库的人的事。
- 卡片是导航，不是事实：要改的文件必须自己读源码。
- 命中标着 `stale` 的卡：先重读源码，再重写这张卡。

**改完**
- 对你改动过的每一个文件调 `dk_put`。
- F 必写（一句话职责）；R 写「必须一起考虑的文件」；A 写对外契约；S 只在「不写会让人改错」时写。
- 新文件没有卡就顺便建一张；确实不值得建卡（生成物、第三方）就 `skip:true`。
- 移动或改名文件：先 `shell mv` 到新路径，再 `dk_put {path: 新路径, from: 旧路径}`——保留 F/R/A/S、自动改写全库指向旧路径的 R；别只 mv 文件不更新索引。
- 只是删卡、又不想让文件被赶出受管范围（文件还在仓库里）：`dk_put {path, remove: true}`——删卡但不写 `.dkignore`；确实不该建卡的才用 `skip: true`。
- 不确定一批改动的影响时，`dk_put` 带 `dry_run: true` 先看 added/updated/removed，再落盘。

**别做**
- 不要编造哈希、行号或字段值——工具会自己算。
- 不要因为没索引就跳过；也不要为了凑覆盖率给不读的文件瞎写卡。

**判断标准**：`dk get` 对你改过的每个文件报 `fresh`（逐文件的新鲜度只有它给）；`dk check` 报覆盖率 100%、过期 0。
