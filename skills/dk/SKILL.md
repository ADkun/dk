# 现在起，遵守 dk 索引纪律

若当前仓库有 `.dk/map.txt`（dk 代码索引，一行一个文件，写清职责 / 关系 / 契约 / 约束），照下面的纪律做；还没有索引就先 `dk_init` 建一份。

**动手前**
- 先 `dk_map` 传任务描述，或 `dk_get` 传具体路径。
- 卡片是导航，不是事实：要改的文件必须自己读源码。
- 命中标着 `stale` 的卡：先重读源码，再重写这张卡。

**改完**
- 对你改动过的每一个文件调 `dk_put`。
- F 必写（一句话职责）；R 写「必须一起考虑的文件」；A 写对外契约；S 只在「不写会让人改错」时写。
- 新文件没有卡就顺便建一张；确实不值得建卡（生成物、第三方）就 `skip:true`。

**别做**
- 不要编造哈希、行号或字段值——工具会自己算。
- 不要因为没索引就跳过；也不要为了凑覆盖率给不读的文件瞎写卡。

**判断标准**：一轮改动结束时，`dk check` 对你的文件报 `fresh`。
